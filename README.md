# ✦ AI Playground

AI Engineering Lab built with Next.js, TypeScript and the Google Gemini API.

This project is a hands-on environment for learning and experimenting with the fundamental concepts involved in building applications powered by Large Language Models (LLMs).

The goal is not only to consume an AI API, but to understand how an AI-powered application is structured, how context is handled, how prompts influence responses, and how the backend can safely manage interactions with AI services.

---

## 🎯 Project Goals

The project was created as the first step in a practical AI Engineering learning roadmap.

The main objective is to learn by building, experimenting and progressively improving a real application.

## 🧠 What the application does

The application provides a simple chat interface where the user can interact with a Gemini model.

Each interaction follows this flow:

```text
User
 │
 ▼
Next.js Client
 │
 │ POST /api/chat
 ▼
Next.js API Route
 │
 ├── validates selected model
 │
 ├── builds conversation context
 │
 └── sends prompt to Gemini
 │
 ▼
Google Gemini API
 │
 ▼
Structured JSON response
 │
 ▼
Next.js API
 │
 ▼
Chat Interface
```

The application also retrieves the available Gemini models dynamically and allows the user to select which model should process the conversation.

## 🏗️ Architecture

The project separates the application into different responsibilities:

```text
src/
├── app/
│   ├── api/
│   │   ├── chat/
│   │   │   └── route.ts
│   │   └── models/
│   │       └── route.ts
│   │
│   └── page.tsx
│
├── components/
│   └── chat/
│       ├── ChatHeader.tsx
│       ├── ChatInput.tsx
│       ├── ChatMessage.tsx
│       ├── EmptyChat.tsx
│       └── ModelSelector.tsx
│
├── lib/
│   └── ai/
│       ├── chat.ts
│       ├── gemini.ts
│       ├── models.ts
│       └── prompt.ts
│
└── types/
    └── chat.ts
```

### Main responsibilities

**`app/api/chat`**

Responsible for receiving chat requests, validating the selected model and returning the AI response.

**`app/api/models`**

Provides the models available for the application.

**`lib/ai`**

Contains the AI-specific logic, including Gemini configuration, prompt construction, model discovery and chat generation.

**`components/chat`**

Contains the user interface components for the chat experience.

**`types`**

Centralizes TypeScript types used by the application.

## 🤖 Structured Output

The AI is instructed to return a predictable JSON structure:

```json
{
  "resposta": "The answer generated by the AI.",
  "categoria": "Technology",
  "confianca": 0.95
}
```

This allows the application to treat the AI response as structured application data instead of relying on unstructured text.

---

## 💬 Conversation Context

The application maintains the conversation history on the client and sends the relevant context back to the backend.

For example:

```text
User: Who discovered Brazil?

Assistant: ...

User: In what year did this happen?
```

The second question is sent together with the previous conversation context, allowing the model to understand what "this" refers to.

This demonstrates an important concept when working with LLM applications:

> Conversation context must be explicitly managed by the application.

---

## 🔄 Dynamic Model Selection

The application does not rely on a single hard-coded model.

Available Gemini models are retrieved dynamically through the API and exposed to the frontend.

The selected model is then sent with each chat request.

Before processing the request, the backend validates that the selected model is actually available.

```text
Gemini API
    │
    ▼
Available models
    │
    ▼
Model Selector
    │
    ▼
Selected model
    │
    ▼
Backend validation
    │
    ▼
Chat request
```

The application also keeps an in-memory cache of the retrieved model list to avoid unnecessary repeated requests.

---

## ⚠️ Error Handling

The application handles different failure scenarios, including:

- Invalid model selection
- AI service failures
- API quota limitations
- Network errors
- Empty requests
- Concurrent requests while another request is processing

For example, Gemini quota errors are represented as HTTP `429 Too Many Requests`, while other service failures can return `503 Service Unavailable`.

## 🚀 Getting Started

### 1. Clone the repository

```bash
git clone https://github.com/josecarlosfreitas/ai-playground.git
```

### 2. Enter the project directory

```bash
cd ai-playground
```

### 3. Install dependencies

```bash
npm install
```

### 4. Configure the Gemini API key

Create a file named:

```text
.env.local
```

Add:

```env
GEMINI_API_KEY=your_api_key_here
```

> Never commit `.env.local` or expose your API key publicly.

### 5. Start the development server

```bash
npm run dev
```

The application will be available at:

```text
http://localhost:3000
```
